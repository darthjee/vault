# `vault up`
Add `vault_up` to `cli/bin/vault` and dispatch `up` from `vault_main`.

Order:
1. When `[dir]` was given and does not exist: `directory not found: <dir>`, exit 1. Put this
   check inside `vault_resolve`, right after `vault_resolve_dir`, for `up` and `run` only, so it
   runs before any docker call. #23 left it to #24.
2. `vault_resolve up "$@"` (return early on `-h`, printing the usage).
3. When a dir is mounted (`vault_mount_dir` is not empty) and none of the four compose file
   names exist in it: the `no compose file` warning.
4. `instance_state`:
   - `running` → `vault-<name> is already running`, then the status block (reuse step 03's
     renderer), exit 0;
   - `stopped` → `docker rm vault-<name>`, then continue.
5. `docker_run_cmd "${CONTAINER_ARGS[@]}"`:
   - Detached success prints `vault-<name> started`.
   - On failure, attribute it per contract 5 (helper `instance_run_failed <status> <stderr>`
     in `instance.sh`). Capture docker's stderr to a temp file, show it, then classify.
   - With `-f`, docker's stderr is still shown and the exit code is passed through, except for
     125–127, which are classified.

Tests in `test/cli/up.bats`:
- the full `docker run` argument list, detached and `-f`;
- already running (message + status, no `run` call);
- stopped (`rm` then `run`, no volume removal);
- the Sysbox failure (runtime `sysbox-runc` + generic error → Sysbox hint, never retried with
  `--privileged`);
- port in use (both strings) → port hint;
- a `--privileged` failure → docker's error only;
- a missing dir (exit 1, no docker call at all);
- no compose file → warning, still runs;
- `--image` without `[dir]` → no mount and no compose warning;
- `-f` passthrough of a non-start exit code (e.g. 3).
