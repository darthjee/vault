# Write ci.md
Create `docs/agents/specs/docker-image/ci.md`. It links to `AGENTS.md` (Release), then adds:
- **CircleCI principles:** the YAML only sets up executors, contexts and filters, and calls make targets. Docker jobs use `machine: true`.
- **PR and branch pipeline (#8):** lint, unit tests, image build, smoke test.
- **Release pipeline (#9):**
  - runs only on `X.Y.Z` tags;
  - chain: `check-version-tag` + `build-and-test` → `build-and-release` → `update-description`;
  - `build-and-release` runs buildx with QEMU on a single machine for `linux/amd64` and `linux/arm64`, and pushes `:X.Y.Z` and `:latest`;
  - no tag is pushed during epic #2.
- **Credentials:** a restricted CircleCI context, used only by the release jobs. This is a change from "project env vars" in `AGENTS.md`.
- **Docker Hub description:** the content of `DOCKERHUB_DESCRIPTION.md`, and `update-description` fetching `darthjee/scripts`' `docker_hub.sh` at a pinned tag or commit through a `scripts/ci/` wrapper. Nothing is vendored.
- **Manual prerequisites:** the Docker Hub repo `darthjee/vault`, the CircleCI project, and the context with the credentials.
