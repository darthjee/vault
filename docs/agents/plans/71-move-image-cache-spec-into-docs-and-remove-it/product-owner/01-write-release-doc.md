# Write docs/agents/release.md
Create `docs/agents/release.md`, the single home of the image build / release rules from epic #65. Short sections, tables for mappings, same style as the other agent docs. Start with a one-line purpose. Sections:

- **Overview** — goal: unchanged layers are reused in CI builds, keep their digest on Docker Hub and are not re-downloaded by users. Three combined mechanisms: layer order, reproducible layers, registry cache.
- **Layer order** — the `Dockerfile` goes from least to most frequently changing: base (`ARG DOCKER_VERSION` / `FROM`), `apk add` (with `APK_REFRESH`), `mkdir -p -m 0755` of `/usr/local/share/vault` and its `completion/`, the completion files (`COPY --chmod=644`), `source/lib/`, `vault-entrypoint`, `vault-install`, then `COPY --chmod=755 build/vault` as the **last content layer**, then metadata. Rules: a new layer goes where its change frequency puts it; the `mkdir` stays before the `COPY --chmod=644` (otherwise the directories get `644`); modes that must not change (table from `image-cache-dockerfile.md`). A `DOCKER_VERSION` bump rebuilds every layer.
- **Reproducible layers** — `SOURCE_DATE_EPOCH` fixed at `0`, env override (`SOURCE_DATE_EPOCH="${SOURCE_DATE_EPOCH:-0}"`) in every entry point; `rewrite-timestamp=true` on the output; `apk add --no-cache --no-logfile` (the log file would embed the build time); the image `Created` date is always 1970-01-01 (use the tag or the push date). `apk` index drift is accepted; `bash` is not pinned.
- **Builder** — one `docker-container` builder `vault-builder` (override `BUILDER`), BuildKit pinned to `moby/buildkit:v0.33.1` (override `BUILDKIT_IMAGE`); created by `make buildx-builder` locally and `scripts/ci/setup_buildx.sh` in releases; used by `make build-image` (and so the tests), releases and `scripts/check_reproducible.sh`. `make build-image` uses `--output type=docker,rewrite-timestamp=true` so the image is still loaded locally. Minimums: BuildKit v0.13+, buildx v0.10+. The default `docker` driver is not used: on the classic image store it ignores `rewrite-timestamp`, so a build that bypasses `vault-builder` is not reproducible.
- **Registry cache** — `darthjee/vault:buildcache`, table per CI job (`build-and-test`: no context, imports anonymously, never exports; `build-and-release`: context `docker-hub`, imports and exports `mode=max`). `scripts/release.sh`: `CACHE_REF="$RELEASE_IMAGE:buildcache"`, always `--cache-from`, `--cache-to ...,mode=max,ignore-error=true` only when `PUSH=true`. `make build-image`: `--cache-from` when `BUILD_CACHE` is non-empty (`BUILD_CACHE=` disables it), never `--cache-to`. Failure semantics: missing / unreachable cache is a BuildKit warning, a failed export is ignored; neither fails the build. The multi-arch cache written by releases is reused by the amd64-only PR build. `DOCKERHUB_DESCRIPTION.md` notes that `:buildcache` is not an image to run.
- **Cache-bust knob** — build arg `APK_REFRESH=YYYY-MM`, declared right before `RUN apk add` and referenced in it; `Makefile` and `scripts/release.sh` default it to `date -u +%Y-%m` and accept an override. A new value rebuilds the `apk` layer and every later one (expected once a month); set a new value to pick up an urgent security fix sooner.
- **Security** — stale `apk` packages bounded by `APK_REFRESH`; no cache poisoning: PR builds never write the cache, only `build-and-release` (context `docker-hub`, release tags) pushes `:buildcache`. Runtime privileges are unaffected.
- **Checking reproducibility** — `scripts/check_reproducible.sh` builds twice with `--no-cache` (same flags and `APK_REFRESH`) and compares `.RootFS.Layers`; exit 0 if identical, 1 otherwise, printing the differing layer indexes. Manual only, not run in CI. Expected results: two builds of one commit give identical digests; after a `cli/`-only change only the `build/vault` layer differs.
- **Why** — short rationale: approaches combined (layer order, reproducible layers, registry cache); rejected alternatives with one line each (inline cache from `:latest`: `mode=min` only, weak for multi-arch; CircleCI Docker Layer Caching: paid, CI-only; shared builder image in another project: cross-repo releases and pin bumps); why the epoch is fixed instead of per-commit (a per-commit epoch changes every clamped layer on a cache miss).

Verify each value against the merged `Dockerfile`, `Makefile`, `scripts/release.sh`, `scripts/check_reproducible.sh` and `scripts/ci/setup_buildx.sh` before writing it.
